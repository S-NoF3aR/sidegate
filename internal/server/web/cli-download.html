How to: remote desktop (RDP)

  1. Start the tunnel{{with .RDP}} to {{(index . 0).Title}}{{end}}. It opens your RDP client automatically:

    {{template "cli-code" (printf "sidegate rdp %s -port 13389" $rdp)}}

    A fixed -port lets your RDP client remember settings and saved credentials for this desktop; use a different port per desktop. Without it, a free port is picked each time.

  2. Remote Desktop Connection (mstsc) opens and connects to 127.0.0.1:13389. Enter your Windows credentials for the remote computer, e.g. CORP\alice.

    FreeRDP (or Remmina) opens and connects to 127.0.0.1:13389. Enter the credentials for the remote computer when asked.

    Windows App (Microsoft Remote Desktop) opens a connection to 127.0.0.1:13389. Enter the credentials for the remote computer when asked.

  3. Your client may warn that the remote computer's identity can't be verified, because it connects to 127.0.0.1 while the certificate carries the server's real name. Check that the certificate name is the computer you expect, then continue.

  4. Keep the terminal open while you work. Press Ctrl+C in it to stop the tunnel when you're done.

Prefer another RDP client, or none opened? Start only the tunnel and connect any client to 127.0.0.1:13389:

{{template "cli-code" (printf "sidegate tunnel %s -port 13389" $rdp)}}

How to: SSH, scp, rsync and VS Code

Quick: one command

Runs your normal ssh through the proxy. Use your usual SSH username and key or password for the server; everything after the app name is passed to ssh:

{{template "cli-code" (printf "sidegate ssh alice@%s" $ssh)}} {{template "cli-code" (printf "sidegate ssh alice@%s uptime # run a command\nsidegate ssh alice@%s -i ~/.ssh/id_work # pick a key\nsidegate ssh alice@%s -L 5432:localhost:5432 # forward a port" $ssh $ssh $ssh)}}

Recommended: SSH config, for every SSH tool

  1. Add this to %USERPROFILE%\.ssh\config (create the file if needed), replacing <you> with your Windows user folder:

    {{template "cli-code" (printf "Host *.%s\n User alice\n ProxyCommand C:\\Users\\\\AppData\\Local\\Programs\\sidegate\\sidegate.exe proxy %%h" .Domain)}}

    Add this to ~/.ssh/config:

    {{template "cli-code" (printf "Host *.%s\n User alice\n ProxyCommand sidegate proxy %%h" .Domain)}}

    Add this to ~/.ssh/config:

    {{template "cli-code" (printf "Host *.%s\n User alice\n ProxyCommand ~/.local/bin/sidegate proxy %%h" .Domain)}}

    Replace alice with your username on the servers, or leave out the User line.

  2. Use every SSH-based tool with the app's address, as if the server were directly reachable:

    {{template "cli-code" (printf "ssh %s.%s\nscp report.pdf %s.%s:/tmp/\nrsync -av ./site/ %s.%s:/var/www/\nsftp %s.%s" $ssh .Domain $ssh .Domain $ssh .Domain $ssh .Domain)}}

  3. VS Code: install the Remote - SSH extension, run Remote-SSH: Connect to Host… and enter {{$ssh}}.{{.Domain}}. VS Code reads the same SSH config.

The first time you connect, ssh asks you to confirm the server's host key fingerprint. Compare it with what your administrator published before answering yes. ssh then remembers it under the app's name.

Troubleshooting

The browser opens again to sign in
Your sign-in expired, or this app requires multi-factor authentication or a recent sign-in. Complete the sign-in and the connection continues.
"you don't have access to this app" or "no app … among your apps"
Check the name with sidegate apps. If the app isn't listed, ask your administrator for access.
The connection drops with "closed by remote host"
Your session ended: you signed out, an administrator signed you out, your access was removed, or your account changed at the identity provider. Run the command again to sign in.
"No RDP client found"
Remote Desktop Connection (mstsc) should be part of Windows; check that it isn't removed by policy. Install one: sudo apt install freerdp3-x11, sudo dnf install freerdp or Remmina. Or use sidegate tunnel and any client. Install Windows App from the App Store, or use sidegate tunnel with another client.
ssh says "kex_exchange_identification" or "Connection closed" right away
The tunnel couldn't be opened. Run sidegate proxy {{$ssh}} on its own to see the error, or sidegate login {{.Portal}} to sign in again.
Sign-in fails on a server without a desktop
The sign-in hands the result to the computer you run sidegate on, so open the printed link in a browser on that same computer.
